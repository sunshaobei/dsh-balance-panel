# GPT/Codex 用量切换与模型参数修复设计

## 用户确认的目标
- 在当前会话选择 GPT/Codex 模型时，底部显示同账号 ChatGPT 订阅用量（5 小时/周等窗口），不能显示 DeepSeek 余额。
- 支持 Codex Auth 写入的共享 OAuth grant：`llm-pi-ai/openai-codex`。不添加第二套凭证存储，不向浏览器发送 token。
- Codex Auth 自动配置 GPT 上下文为 1,000,000 tokens；最大输出按逐型号可核实的官方规格设置，不能编造未知/自定义别名的上限。

## 已验证问题
1. 用量查询函数认识共享 grant，但 ChatGPT 行发现函数只检查两个旧文件，导致共享授权账号的 ChatGPT 行提前被过滤。已用纯模拟凭证、真实函数验证。
2. 当前模型绑定按会话更新时间排序，不保证等于可见会话；DOM 兜底不接受含空格的显示名；服务无当前模型时不清旧值。
3. 401 重试只是清缓存，可能继续使用同一个未过期但已被拒绝的 token。
4. 代理 CONNECT 请求错误携带目标 Authorization/account header，需要与隧道内目标请求隔离。

## 方案比较与选择
- 仅阻止空 provider 匹配：不会错配，但仍然无数据；不足以满足目标。
- 只读 DOM 模型名：易受显示名、别名和页面其他按钮影响；不作为主要来源。
- 采用方案：修复凭证发现 + 当前会话结构化模型状态绑定；DOM 仅限定到 composer 作为兼容回退；GPT 命中 ChatGPT 固定分组。保留其他供应商与已有授权来源。

## 实现边界
- 修正 host 的 shared-grant discovery/status；共享凭证撤销/替换后不继续使用旧账号缓存。
- 401 最多刷新重试一次，同账号刷新失败必须显示失败，不静默跳到其他来源账号。
- 仅向 TLS 隧道内的目标请求发送目标 Authorization；CONNECT 仅发送代理必要字段。
- 余额面板用当前会话、当前模型的真实绑定；切换无匹配时清旧数据显示等待/不可用，不冒充其他供应商。
- Codex 模型参数使用宿主支持的 provider/model 配置接口，保留已有配置与分组；未知输出规格不擅自填数。
- 保留当前未提交的 scoped loader-id 与构建注册校验改动。
- 不改其他四个插件，不改全局代理或 launchd 环境，不评论已关闭 issue。

## 验证与验收
- 先用真实函数及合成数据写失败回归测试，禁止读取真实 token。
- 覆盖 shared-only 授权发现、DeepSeek/GPT 双行并存、当前会话切换、含空格 GPT 名称兼容、清除旧绑定、401 刷新一次和代理头隔离。
- 使用真实 TypeScript 构建，验证 npm 打包内 scoped loader 注册及源/产物一致。
- 明确区分模拟测试通过与桌面真实 OAuth/用量请求验证；未看到真实结果前不得声称已成功。

## 自审
无待填占位符；输出参数若没有官方可验证依据，必须报告并保留宿主原值。部署/发布需在测试与变更审查后执行，不能以版本递增代替验证。
